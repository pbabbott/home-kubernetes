## Lessons from Phase 8 (read before any traffic or DNS step)
1. **After an origin change, drain the old origin before stopping the old backend.** The eero forward only moves NEW connections. Cloudflare kept persistent connections to `.28` (4 sessions, Cloudflare IPs), and stopping gen2 gave ~1/3 of requests a 503 for ~10 min. Check `haproxy_backend_current_sessions` is 0 on the old LXC and that a 40-request loop is all 200 before stopping anything. This applies again to retiring `.28`.
2. **Cert issuance:** apex and wildcard orders share `_acme-challenge.abbottland.io`; the first wildcard order failed at finalize. Fix = delete the failed CertificateRequest, then the Certificate (the gateway shim recreates it; the old secret keeps serving).
3. **external-dns takeover:** use the old `txtOwnerId` to adopt records; go live `upsert-only` first; the txt registry uses prefix `_extdns.`.
4. Prune order: workloads with finalizers/controllers first, the controller in a LATER merge. Prefer HARD node affinity on small nodes (worker-3 is 6 GB on chimaera, controller-3 ~3 GB).
5. A Pi-hole `.28 -> .29` overwrite fails ~1 in 5 times: if a record is not `.29` after ~2 cycles, delete the `.28` record via the API (DNS refuses for ~5-10 s after changes: poll `dig @192.168.4.144`).
6. `HOSTS.md`: eero does NOT hand out Pi-hole DNS by default (opt-in per device). Tailscale (bananapi subnet router) reaches `*.local` from outside the LAN: verified by the user 2026-11-09.
